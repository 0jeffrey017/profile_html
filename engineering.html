02 / CODE DESIGN

廻り月

FSM / UniTask / CancellationToken

設計・実装
遷移要求をキューに入れて一つずつ処理します。現在の状態の終了と次の状態の開始を待ち、要求元に完了・例外・キャンセルを通知します。
コードの着眼点

  4. 04完了を通知

掲載用コードサンプルの一部を抜粋しています。

private async UniTask TransitionTo(EGameState nextState, CancellationToken token)
{
    // 遷移中はゲームプレイを停止し、旧状態の終了を待つ。
    _pauseService.SetPaused(true);

    if (_currentState != null)
    {
        await _currentState.OnExit(token);
    }

    _currentState = _stateFactory.Create(nextState);
    _currentStateType = nextState;

    // 次の状態の初期化と演出を待ち、プレイ可能な状態なら操作を再開する。
    await _currentState.OnEnter(token);
    _pauseService.SetPaused(nextState is not EGameState.MainGame and not EGameState.Tutorial);
    }

Unity Job System & Burst Compiler

IJobParallelFor / Burst / NativeArray

考えたこと
大量のボールの計算を並列に進め、結果をいつ画面に反映するか。
設計・実装
IJobParallelForでボールの物理計算を分担します。Updateでジョブを登録し、LateUpdateで完了を待って結果を反映します。一時配列の解放にもジョブの依存関係を渡します。
コードの着眼点
ボールの当たり判定をColliderを使わず、GPUにデータだけ渡す計算すること。Unityで計算したデータを反映する
  1. 01入力データを用意
  2. 02ジョブを登録
  3. 03計算の完了を待つ
  4. 04結果を反映

06 / RESOURCE MANAGEMENT

オブジェクトの再利用

Shark Avoid Game

ObjectPool / 生成・返却 / 初期化

考えたこと
出現と消滅を繰り返す食べ物を、毎回作り直さずに扱うには。
設計・実装
Unity標準のObjectPoolを使い、取り出すと表示、返却すると非表示にします。新規生成時のレイヤーや当たり判定の設定は、初期化処理にまとめます。
コードの着眼点
新規生成するときだけ行う処理と、再利用のたびに行う処理の違い。保持数の上限を超えたオブジェクトは破棄します。
  1. 01プールから取得
  2. 02表示・位置を設定
  3. 03ゲーム内で使用
  4. 04非表示にして返却
コードの抜粋を読む C# / Shark_GObjectPool.cs

        _pool = new ObjectPool<GameObject>(
            createFunc: () => Initialization(prefab, layerID), // 新規生成時のみ呼ばれる
            actionOnGet: g => g.SetActive(true),               // 取り出し時：再有効化
            actionOnRelease: g => g.SetActive(false),          // 返却時：非表示にして保持
            actionOnDestroy: Object.Destroy,                   // 上限超過時：破棄
            collectionCheck: false,
            defaultCapacity: _defaultNumber,
